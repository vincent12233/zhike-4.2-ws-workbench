# 知客 6.0.0 Horizon Atelier 发布说明

6.0.0 保留现有知客业务规则与统计口径，但使用全新的独立数据空间。正式产品只有一套 WinUI 3 + WebView2 + 本机 SQLite 运行链，不包含 Electron、Docker、PostgreSQL、第二套客户端或可回退的旧页面入口，也不预置演示数据。

## 视觉与交互

- 使用 Horizon Atelier 设计系统：黑曜石底色、克制青蓝/紫色流光与少量香槟金。
- 侧边栏完整保留工作、客户、业务数据、系统管理全部模块，可折叠并记忆状态。
- 今日工作台的“AI 跟进流域”、客户、金额、数量、趋势和任务全部来自本机真实数据；无数据时显示空状态。
- 统一页面与内层滚动所有权，避免滚轮串到外层；列表分页/虚拟化优先保证 10,000 与 50,000 客户规模的流畅性。

## WS 与 AI

- 用户扫码登录后，前台 WhatsApp 可以正常聊天；独立采集器在应用打开期间持续同步会话列表、联系人索引和双方实时消息。
- 用户无需手工逐个打开会话。完整历史由后台不可见采集任务按断点依次加载；未读会话不会自动激活。一对一会话与系统设置中明确绑定的 VIP 群可进入完整历史采集，普通群和类型不明会话不进入分析、补档或提醒。
- VIP 群消息按可信 JID/手机号拆分成员；只有唯一匹配到现有客户的成员才进入该客户档案和个人跟进评分，不自动新建客户，也不跨成员归因。
- 列表预览、实时消息和完整历史使用不同覆盖状态；只有完整原文、方向和顺序成功落库后才允许完整 AI 分析。
- AI 只补唯一匹配的现有客户空字段，不新建陌生客户、不覆盖人工/锁定字段；每项事实保留证据、来源与置信度。
- 跟进优先级按资金实力 55% 与聊天粘度 45% 计算；股票投资年限只补充档案，不计入提醒分数。提醒写入今日工作台和任务中心，默认不自动发送消息。

## 业务与数据

- 客户主档案通过号码/身份关联，跟票、入金、报名和跟进仍是独立业务记录；同一客户的不同股票与买卖批次不会合并。
- 手机号登记保持独立，不使用客户中心 AI 导入规则。
- 导入按行识别客户、跟票、入金及混合业务；登记日期与下次跟进日期分离，渠道和群粉子类读取系统设置。
- 6.0 首次启动在 `%LOCALAPPDATA%\Zhike6` 创建空 SQLite 库；不读取、不迁移旧 `%LOCALAPPDATA%\Zhike`，也不主动删除旧目录。
- 已移除旧 SQLite 导入、本机/Docker 合并和 WebView 业务缓存迁移端点；数据中心只恢复 6.0 自身 JSON 备份，恢复前验证 SHA-256 完整性。
- 批量写入前创建快照；覆盖升级与卸载不删除 `%LOCALAPPDATA%\Zhike6`。

## 已知限制与实机验收

- 个人 WhatsApp Web 没有官方“直接导出全部历史”接口；完整历史需要由隔离采集器在后台依次加载会话，电脑关闭、休眠、断网或会话过期时不能继续。
- WhatsApp 页面结构变化、真实手机新消息、扫码登录和外部 AI 服务额度必须在目标机实机验证。
- 未签名个人安装包可能被 Windows 提示；必须先核对交付目录 SHA256，不关闭或绕过系统安全保护。
- 编译成功不等于验收通过；最终结果以 `docs/test-report-6.0.0.md` 和交付目录安装验收记录为准。
