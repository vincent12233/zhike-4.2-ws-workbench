# 群组草稿备份与恢复

群组草稿是本地历史，不是发送队列。`/api/ws/export` 的 v6 / exportVersion 2 格式新增可选 `groupDrafts` 数组和 manifest 计数，流式导出当前账号全部草稿，而非页面最近 30 条。手工与原生全工作区备份均原样携带每个账号的导出对象，保留原文空白、确切群 JID、标题快照、创建和取消时间。旧备份仍可恢复。

## 单账号恢复保证

- 群组草稿仅恢复到同编号、同专用用途的账号；每一条的 `accountId` 必须完全匹配。
- 缺少 `groupDrafts` 或空数组表示不增加历史，不删除现有草稿。
- 所有草稿先校验；导入在已有 SQLite 账号事务内合并。任何同编号不同原文或目标 JID 的冲突，使该账号的会话替换、已插入草稿等全部回滚。
- 同编号同内容重复恢复不新增行。已有标题快照和创建时间保持原值。任一侧已取消，最终均保持 `CANCELLED`；旧 `DRAFT` 备份不能复活取消状态。
- 允许恢复已经离开或本机尚未发现的群的历史草稿，因此不要求当前群目录存在；不会重新创建群目录、监控授权、发送计划或发送记录，也不会调用原生传输。
- 返回 `groupDraftRestore`，明确 `mode: merge`、接收/插入/取消/未改变数量和 `sendAvailable: false`。

## 全工作区恢复边界

原生备份文件和手工备份文件共用页面恢复流程。恢复先从逐账号导入中剥离 `groupDrafts`，暂存于本次操作；全部账号及 CRM 写入成功后，最后调用 `/api/ws/group-drafts/restore`，在一次 SQLite 事务内合并全部账号的草稿。第二账号或 CRM 失败时，草稿从未写入。最后事务任一账号冲突时，所有账号本次草稿写入全部回滚，页面再补偿已恢复的 CRM 和 WS 数据。补偿失败会明确报告，不声称全部回滚成功。

末步请求以完整账号草稿集合的 SHA-256 作为 `operationId`，服务端核验指纹且只调用同源校验和合并函数。请求失响应时，页面以完全相同的操作和内容重试一次；合并自身幂等，无发送副作用，也不会复活取消。若仍无法确认，保留已恢复数据，明确提示“草稿提交结果未确认，未执行回滚”，允许重新导入同一备份复核。即便第一次失响应后重试收到冲突，也不假定首次未提交。没有向普通导入暴露可删除历史或复活取消的 `rollback` 字段。

原子性声明只覆盖最终的跨账号群草稿集合；全工作区的 CRM 与会话仍通过多个 HTTP 请求和补偿完成。界面恢复前调用的 `/api/snapshot` 只把 CRM `readState()` 写入 `state_snapshots`，不是完整数据库快照，不能用它宣称全库精确原子回滚保障。

## 合成回归入口

- `tests/ws-group-drafts-backup.test.cjs`：真实鉴权 HTTP 与临时 SQLite，跨账号隔离、32 条完整导出、旧格式、逐项校验、单账号及跨账号事务冲突、取消单调性、重复恢复和无发送副作用。
- `tests/ws-group-drafts-restore-core.test.cjs`：真实 SQLite 回滚，生产 `restoreBackupFile` 的账号/CRM/末步失败、丢响应幂等重试与未知结果；生产 API 不继承前台账号。
- `tests/native-backup-restore.test.cjs` 与 `desktop/tests/BackupRetentionRuntime`：真实 .NET 封装、完整性校验、生产 JS 解码、两个账号往返及重复恢复，包含 DRAFT / CANCELLED 和无当前群目录。
- `tests/manual-backup-all-accounts.test.cjs`：生产手工备份动作完整保留每账号草稿及完整性摘要。

所有数据均为临时合成内容，不使用真实客户库或 WhatsApp profile。真实群发送、提及和逐人已读能力仍未验证，保持不可执行。
