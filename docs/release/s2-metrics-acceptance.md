## 实际实现与权威边界

- 从原 `renderHome` 提取 `prepareHomeMetrics`，继续调用原 counts、有效客户、CRM、业务索引、状态历史与日期函数，不建立第二份统计主档、查询消费者或数据库。原首页本周入金包含待确认的行为保留，并明确标注“周一至今日 · 含待确认”，不能自行改成已确认金额。
- `__zhikeRegistryHost.getMetricsProjection` 提供冻结的只读 DTO。其范围明确是 **全局 CRM 客户主档与原业务记录**，不假装支持 WS 账号数据；拒绝不支持的 scope/account/filter 参数。投影不 fetch、不写状态、不创建 AI 提醒或 Worker 任务。
- 每项指标记录来源、有效/删除规则、日期字段、范围、去重口径和分母是否可计算。近七日客户按登记日期、跟进按原 followups 记录日期；二者不是转化漏斗。原客户状态可以重叠，展示为状态覆盖而非逐级转化。
- 本机读取生命周期区分加载、已读取、错误、待写入与保存冲突；错误和未确认数值为“—”，不能把未知当 0、把缓存现值冒充上次成功值。读取时间来自真实已应用响应，不是每次渲染时间。迟到请求不能标记新数据成功或改写读取时间。
- 首次读取失败后的完整响应恢复沿既有 apply/version/pending/conflict 边界接入；周期刷新仍保留 WS 页不重绘外壳的抖动防护。没有增加轮询或正式消费者。
- 新 `metrics-charts.js` 是单一纯 SVG/HTML 渲染模块，复用已有 CSS tokens，没有新增框架、远端 CDN 或第三方依赖。提供折线、横条、完整类别分布及进度，只有真实数据适用时才显示；缺失不补 0，抽样/截断明示，无法计算分母不画假占比。不会捏造阶段历史、迷你趋势或不具备数据的漏斗。
- 图形与明细有界（最多120个趋势点、40个类别），标签转义、数值校验、键盘焦点、标题/图例和可展开表格复用同一值。窄图形水平滚动保留可读字体，不靠缩字塞入卡片。完整页面空间和钻取/筛选由 S3–S6 沿原业务入口继续接线，不把只读图形变成业务写入口。
- 新资源通过原静态文件白名单提供，并纳入真实隔离 HTTP 检查。历史迁移、checksum、业务协议、生产开关及密钥存储未修改。

## 已复现问题与最小修复

1. 首次后端读取失败后，后续完整响应没有正确应用：以实际版本/待写/冲突守卫修复恢复路径。
2. 原 `today` 尚未被既有分钟 tick 更新时，新趋势用实时日期造成跨午夜口径不一致：投影统一使用原 asOfDay，未新增日期计时器。
3. 错误或未确认 coverage basis 仍带数值 0：分子、分母置未知，不伪造可计算比率。
4. 过期异步读取抢先更新成功来源与时间：先验证请求顺序及是否实际应用，再更新来源状态。
5. 原全局 SVG 图标 stroke 被图表文字继承：真实全量 CSS 红用例复现，仅在图表 SVG 根和文字既有规则重置 stroke，曲线、网格与数据点保留自有描边。
6. 原首页排序重复计算客户优先级：仅在本次 prepare 的局部 Map 中复用原评分，再按原比较器排序原数组并取前五，不修改评分、日期或金额规则。33组旧比较器对照验证完整排序、同分稳定性、旧字段与固定时间边界；相同 revision 复用，失效后重算。

每项均有保留的失败与修复后证据；没有删除测试、改成功固定返回值或扩大生产权限。
