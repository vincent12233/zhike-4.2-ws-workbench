# 知客 6.1.0 A+B 预发行说明

当前预发行目标为 `v6.1.0-rc.3`，程序与安装器版本保持 **6.1.0**。候选发布状态以 GitHub 实际记录为准。[rc.3 候选入口](https://github.com/vincent12233/zhike-4.2-ws-workbench/releases/tag/v6.1.0-rc.3)的安装资产为 `zhike-6.1.0-win-x64-setup.exe`，随附 `release-output-manifest.json`；完整源码提交、文件大小、SHA-256 和实际签名状态以同次清单及实际签名核验为准。已发布的 [rc.2](https://github.com/vincent12233/zhike-4.2-ws-workbench/releases/tag/v6.1.0-rc.2)属于历史候选，不包含本轮独立采集与生产群组查询修改。两次候选版本号和文件名相同，请用标签和同次清单区分。

## 首次启动

Windows x64 内部版本须为 22621 或以上。请先安装 Microsoft Edge WebView2 Evergreen Runtime，再运行知客安装器。缺少运行时时知客安装会中止。安装完成后，从桌面或开始菜单打开“知客工作台”。本机 SQLite 在 `%LOCALAPPDATA%\Zhike6`。首次使用此目录为干净空库，旧 `%LOCALAPPDATA%\Zhike` 数据不会自动读取或迁移。

先进入“客户中心”或“快速录入”，用本机资料验证录入与保存。升级或换机前在“数据中心”导出备份。换机后需要重新登录 WhatsApp 并配置 AI Key。完整步骤见随包《本机部署说明》和《故障排查》。

## rc.3 新增实现

- 独立后台采集会话由用户再次扫码登录，与前台聊天分别保存会话及显示状态。请使用当前所选账号的手机扫码；原前台登录资料不会复制给采集端。
- 采集端就绪后，可发现会话、采集已读历史及监测所选群组，支持暂停、恢复、账号隔离与退出回收。未读跳过、去重、范围限制和断点规则保留；不回退到前台聊天视图采集。
- 生产群组管理读取本机群目录、成员关系、同步记录与审计，展示实际已观察的关系。它不保证完整实时花名册，不伪造邀请、移除成员或发送成功结果。
- 全新空库的登记迁移在一次事务中初始化，失败或中断时完整回滚；已有数据库继续按原逐版本事务升级。历史迁移内容和 checksum 不变。

操作步骤和已执行的隔离回归见[独立采集会话说明](independent-collector-followup.md)。采集完成不会自动发起付费 AI；用户显式分析继续使用已有确认流程。

## 保留的 rc.2 修复

安装目标必须为空目录或当前用户已登记的同一知客安装目录；系统、数据、链接路径和新旧目录相交受到保护。新版文件部署成功后才处理旧 Electron 客户端。首次启动显示本机服务连接和页面读取状态，加载失败保留重试入口。客户编辑、VIP 冲突、并发保存、WS 导航和本机 sidecar 启动保护继续保留。

业务页面和本机数据可离线使用。手动导入保留获准处理的原文。查看已保存的联系人、群组、审计和 AI 建议无需开启自动 AI。显式联网 AI 由用户配置供应商、确认权限和请求范围。

## 已知限制与验收

认证 profile 复制保持禁用。生产 Worker 和自动 AI 消费者保持关闭。真实 WS 登录与收发、独立扫码、双会话同时在线与实际采集、付费 AI、干净 Windows 安装与覆盖卸载、跨设备和完整多 DPI 或物理输入仍待验收。Windows 2025 runner 的安装、覆盖与卸载检查使用外部合成数据哨兵；结果以对应运行记录为准。源码隔离回归、Windows 构建和合成安装检查不能替代真实目标机与用户数据升级验收。

S3 保持 Blocked。历史隔离 Edge 退出故障及 rc.2 安装就绪记录仍保留供追溯，不能作为 rc.3 验收结论。候选提交、资产校验和签名结果须以本次实际构建及对应预发行记录为准。

以下变更位于集成分支 `feature/zhike61-ws-completion`，**尚未作为 GitHub Release 发布**，不属于 `v6.1.0-rc.3`。当前候选构建为源码 `2b8817e`，安装器 SHA-256 `E8BED3499A96ABCFC3AEE802AD7FE31E3CBA7066D6A26C9EB738D08FD92B7707`，详见 [V9.2 集成报告](../audit/2026-11-21-v92-integration-report.md)。

### 专用 WS 与群组

- 普通 WS 与专用 WS 分用途登记账号；账号登记、已保存会话、在线视图与采集会话分别显示，不互相推定。
- 专用 WS 新增“群组渠道配置”（schema 34）：群组的渠道、页面分类与默认标签驱动自动建档与渠道归属，改名不丢历史。
- 专用 WS 新增“群组管理”（schema 35）：只维护渠道、群名、群别名三项；支持新增、编辑、停用与启用、先预览再提交的批量导入。不要求填写 JID，不按别名前缀推断渠道，不设负责助理。
- 快速录入时群别名精确匹配到本地群组，客户记录稳定的群组 ID、别名和该群配置的渠道；不匹配时保留原文，不写入 JID 或在群状态。客户 360° 显示群组登记。
- AI 同名候选只作建议；确认绑定需要真实 `@g.us` 群标识，且可解除绑定。
- 群组草稿、@ 提及能力与权限状态、群组已读、在群客户表与运营状态条。

### CRM 与 AI

- 客户字段锁定：被锁定的字段不会被 AI、导入或自动补齐改写；客户合并也不改写保留客户已锁定的字段。
- 身份冲突与疑似重复只提示，不自动合并；客户 360° 显示投资画像、WhatsApp 身份、字段来源、冲突与变更历史；资料完整度评分。
- 渠道、助理与群组统计采用明确的去重规则；跟进提醒分五种状态，不凭空生成日期。
- AI 同步不再填写或争用客户渠道与负责人，较旧消息的 AI 结果不会覆盖较新的值；私聊分析需授权并受预算约束。
- VIP 群概念已移除，VIP 只是客户标签。

### 修复

- 撤销客户合并只恢复本次合并涉及的客户与记录归属，保留合并后修改的无关设置；有冲突时拒绝并保留撤销点。
- 群组管理页在安装版可加载并可操作（静态白名单、响应读取与事件绑定三处缺陷）。
- `ai-job-pipeline-core.js` 在页面中不再报 `module is not defined`。

### 升级与回退

数据库由 rc.3 的 schema 25 升级到 35。升级后 rc.3 及更早构建会拒绝打开同一数据目录（`SCHEMA_VERSION_UNSUPPORTED`）。试装前请导出备份；回退只能使用对应版本及升级前的备份恢复。Windows CI 机已完成合成数据的安装、rc.3 覆盖升级与卸载检查；真实目标 Windows、用户数据升级、真实 WhatsApp 与付费 AI 尚未验收，S3 保持 Blocked。
