## 结果记录规则

- 每项只填 **PASS / FAIL / BLOCKED / NOT_TESTED** 之一，并写明实际看到的现象。
- PASS 只用于实际操作且结果与“预期”一致的项；缺少账号、设备或权限而未做的，填 BLOCKED 并写明原因；未做的填 NOT_TESTED。
- FAIL 时保留截图、界面原文错误、操作时间、Windows 版本，以及 数据中心 → 诊断 的导出结果。当前版本**没有** `%LOCALAPPDATA%\Zhike6\logs` 日志目录，不要在其他位置寻找或伪造日志。
- 真实 WhatsApp 相关项只能记录“实测现象”，不能根据界面已连接就推定功能通过。
- 处于功能冻结期：发现缺陷只记录、复现并回报；修复后会产生新的 commit 与 SHA-256，须用新安装包重新验证受影响项。

## 数据安全规则（必读）

1. **任何涉及真实数据的操作前，先完成第 0 步备份并核对备份可用。**
2. 不删除、不清空、不覆盖 `%LOCALAPPDATA%\Zhike6`。需要“空白环境”时，使用另一台电脑、另一个 Windows 用户或虚拟机，或先把整个目录**改名**保留，不要删除。
3. 旧版真实数据库的升级先在**副本**上做（第 9 步），确认无误后再决定是否升级正式数据。
4. Schema 35 不能回退：数据被本候选升级后，rc.3（schema 25）和 rc4–rc8（schema 34）会以 `SCHEMA_VERSION_UNSUPPORTED` 拒绝打开同一数据目录，表现为启动后白屏。回到旧版只能用旧安装包加上升级前的目录副本或 JSON 备份。
5. 合并、撤销、导入、群组编辑等写入测试只使用名称明确的测试客户和测试群组（例如姓名以“验收测试”开头、群别名以 `TEST-` 开头），不改动真实客户。
6. 真实 WhatsApp 测试使用测试账号和测试群组，不向真实客户发送消息。
