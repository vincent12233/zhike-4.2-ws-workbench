# 专用账号登记规模诊断

此脚本仅测量真实本机 Node/SQLite 服务的登记和查询能力。它不启动 WinUI、WebView 或 WhatsApp，不读取真实用户数据库、登录目录或客户资料，也不执行采集、AI 请求或群操作。

从仓库根目录使用 Node 24 运行：

```powershell
& .tools/node24/node.exe scripts/diagnostics/ws-account-scale.cjs --output work/diagnostics/ws-account-scale.json
```

输出路径必须尚不存在。可加 `--samples 15` 增加每项查询样本；默认每项 7 次，并先进行一次不计入统计的预热。脚本固定依次测试 1、5、10、20、30、50 个专用登记账号；默认普通账号独立统计，总账号数为 2、6、11、21、31、51。

脚本自行创建临时合成数据库，通过产品 API 登记账号，为每个专用账号创建一个停用的监测配置及三个停用的合成群目录目标。目录来源是手工配置，不是 WhatsApp 发现结果。脚本不提供复用现有数据目录的选项，并清除子进程继承的 `ZHIKE_*` 配置；原生写入凭证为空，生产 Mock/Worker 开关保持关闭。

JSON 报告记录：

- 新空库首次启动，以及每档登记数量下重启至 `/api/health` 就绪的耗时。只有空库首次启动包含建库迁移；后续为同一合成库逐级增长后的启动。
- HTTP 账号枚举、首个及末个专用账号的限定群目录查询、空会话查询耗时；另使用只读 SQLite 连接测相同账号/群目录 SELECT。HTTP 包含本机传输和 JSON 开销，SQLite 包含 prepare/all；二者并非同一口径。
- 各查询的原始样本、最小值、中位数、均值、最大值和 p95。小样本 p95 只作诊断，不能视为容量 SLA。
- Windows 允许时，通过所启动 sidecar 的 PID 及父 PID 校验获取累计 CPU 时间、工作集、峰值工作集、私有内存。区间 CPU 百分比以单核为 100%，其区间包含查询与计数器采样开销。不可获取时明确写 `UNMEASURED`。
- 仅检查本脚本所拥有 sidecar 的后代进程，并记录采样时 WebView 后代数；不关闭或操作任何用户应用，也不声称检查了所有时刻或整个桌面。
- 每次认证关闭的返回与退出码、是否曾强制结束自己启动的进程、锁文件清理及最终临时库删除；消息、群事件、采集运行、AI 队列均须为空，监测配置和目标均停用。

报告中的 `PASS` 仅表示上述合成登记/本地查询及清理断言通过。已保存登录有效性、实时在线账号数、前后台 WebView 初始化数、真实切号延迟、采集吞吐/并发、真实群操作和移动端通知都标为未测。此报告不能证明 50 个 WhatsApp 账号能同时登录、在线或采集。

脚本不访问外部网络；若当前执行沙箱禁止 loopback，请在获准运行本机测试的终端执行原命令。失败也会保存报告，不会改换 Mock 后端或降低断言。
