# ChatKnow 风格多 WS 工作台设计

## 意图

把现有知客 WS 工作台整理成 ChatKnow 类似的个人客户服务工作台：左侧管理多个个人 WS 登录账号和会话，中间固定显示当前账号的 WhatsApp Web 页面，右侧显示知客客户资料、翻译、AI 分析和跟进信息。所有账号继续使用个人授权的 WhatsApp Web 登录，不读取密码、Cookie、二维码或秘密 Token。

## 目标

- 同一知客窗口支持多个 WS 登录账号。
- 每个账号使用独立、持久化的浏览器分区，登录状态互不串用。
- 账号可新增、重命名、切换、重新连接、退出和清除本地会话。
- 当前账号的 WS 页面固定停靠在工作台中下部，不跟随知客外层页面滚动。
- 左侧会话列表、中间聊天区域、右侧客户与 AI 卡片采用 ChatKnow 类三栏结构。
- 自动采集、手动导入、AI 分析、客户匹配和跟进提醒都绑定当前 WS 账号与会话。
- 同一个电话号码仍只关联现有知客客户，不创建重复客户。
- 原有知客客户库、跟票、入金、任务和统计口径不改变。

## 非目标

- 不实现团队协作、多人共享账号或云端同步。
- 不读取 WhatsApp 密码、Cookie、二维码或浏览器秘密存储。
- 不绕过验证码、平台权限、页面安全验证或 WhatsApp Web 的加载限制。
- 不把个人 WhatsApp Web 改造成官方 WhatsApp Business API 服务。

## 约束

- 继续使用 Electron `BrowserView`，不替换现有知客桌面框架。
- 每个 WS 账号使用 `persist:ws-workbench-<accountId>` 分区。
- 只有当前账号的 BrowserView 可见并接收采集操作。
- WS 页面只通过已有安全 preload 暴露页面状态、可见列表和可见消息。
- 新增数据必须兼容现有 SQLite 迁移机制，并提供迁移文件。
- 自动采集失败不影响知客原有页面和客户库。

## 方案比较

### 方案 A：同一工作台多账号标签页（采用）

左侧账号栏选择当前 WS 账号，主进程为当前账号创建或恢复对应分区的 BrowserView。账号切换时隐藏旧视图、显示新视图并重新计算停靠边界。优点是最接近 ChatKnow，客户库和 AI 右栏可以保持在同一个工作台；代价是需要管理账号生命周期和多账号数据上下文。

### 方案 B：每个账号独立窗口

每个账号单独创建 BrowserWindow。隔离性强，但窗口切换、客户库联动、固定布局和个人使用体验都更复杂，因此不采用。

### 方案 C：官方 WhatsApp API

适合企业账号和后台 webhook，但不满足个人 WhatsApp Web 登录目标，也无法直接复用当前个人网页登录状态，因此不采用。

## 数据设计

新增迁移 `008-ws-accounts.sql`：

- `ws_accounts`：账号编号、显示名称、分区名、入口地址、连接状态、最近连接时间、是否启用、创建和更新时间。
- `ws_account_settings`：账号级翻译开关、目标语言、AI 开关、自动采集开关和界面偏好。

现有 `ws_conversations`、`ws_messages`、`ws_analyses`、`ws_replies`、`ws_collection_runs` 和 `ws_collection_items` 增加 `account_id`，迁移旧数据到默认账号 `default`。原有唯一约束改为账号范围内唯一，避免不同账号的同一手机号互相覆盖。

## 主进程接口

- `zhike-ws-account:list`
- `zhike-ws-account:create`
- `zhike-ws-account:rename`
- `zhike-ws-account:switch`
- `zhike-ws-account:close`
- `zhike-ws-account:clear-session`
- `zhike-ws-account:status`

返回值只包含账号编号、显示名称、连接状态、分区状态和时间，不返回 Cookie、Token 或密码。

## 页面结构

- 顶部：当前账号、连接状态、采集状态、翻译模式和左右栏收起按钮。
- 左栏：WS 账号列表、会话过滤、未读、待跟进和采集摘要；支持收起。
- 中栏：当前账号的 WS 页面固定停靠，下面保留采集和手动导入操作。
- 右栏：翻译、AI 分析、客户资料、标签、跟进和回复建议；支持收起。

## 自动采集规则

- 登录成功后自动发现当前账号 WhatsApp Web 已加载的会话列表。
- 当前打开的一对一聊天按账号上下文采集可见消息。
- 内容未变化时不重复分析；重复消息按账号、会话和消息标识去重。
- 列表预览自动按手机号、账号标识和会话标识匹配知客客户。
- 无法唯一匹配时只提示人工确认，不自动合并。

## 错误恢复

- 账号连接失败只标记该账号，不影响其他账号和知客页面。
- BrowserView 崩溃后只重建当前账号视图。
- 账号清除会话只清除该账号分区。
- 数据保存失败保留原文和本地草稿，支持重试。
- 切换账号过程中禁止把旧账号的消息、AI 结果或客户资料写入新账号。

## 验收标准

- 可创建两个以上 WS 账号并分别扫码登录。
- 切换账号后登录状态、会话列表、采集任务和翻译设置不串号。
- 关闭当前账号后其他账号仍可使用。
- 清除一个账号的会话不影响其他账号和知客客户库。
- 左右栏收起后 WS 页面固定在工作台中下部，不跟随外层页面滚动。
- 自动采集和手动导入均能正确关联客户并保持原有业务数据。
- 全项目回归测试、迁移测试、安装包测试通过后才能发布。
