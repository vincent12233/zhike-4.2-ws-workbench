# WS 工作台双层重构设计（方案 A）

## 目标

把 WS 工作台从“聊天、采集、导入、AI、档案和任务同时挤在一个页面”重排为双层工作台：前台聊天始终占据最大可用空间，后台采集和 AI 自动化有独立的可见状态，辅助信息可以收起，不改变现有客户、群组、VIP、翻译、群发、AI 补档和任务业务规则。

## 当前问题

- 顶部账号与采集控制占用多行，压缩了 WS 前台。
- 本地导入、消息、采集流程和辅助内容同时展开，造成高度竞争。
- 辅助面板与聊天区域属于同一视觉层级，用户难以判断哪些操作会影响前台 WS。
- 采集状态依赖页面内部内容，容易被误解为前台滚动、打开会话或抢焦点。
- 多个滚动区域边界不清，收起状态不统一。

## 采用方案

### 方案 A：双层工作台（采用）

1. **操作层**：标题、全局搜索、账号切换、扫码登录、连接、后台采集、暂停、重连和队列状态集中在一条固定操作带。
2. **工作层**：中间为最大的嵌入式 WS 前台；左侧仅保留会话导航；右侧为可收起的辅助抽屉。
3. **证据层**：辅助抽屉按“AI 分析、客户档案、回复建议、群发中心、采集诊断”切换，所有 AI 结论显示证据、匹配客户、置信度和待确认项。
4. **流程层**：底部用一条可彻底收起的流程条显示列表同步、完整历史、AI 分析、档案补齐和跟进任务，不再放大块本地消息面板。

方案 B（三栏固定驾驶舱）会持续压缩聊天窗口；方案 C（分屏工作区）需要频繁切换，均不符合 WS 前台连续聊天的目标。

## 页面结构

```text
┌────────────────────────────────────────────────────────────┐
│ 品牌 / WS 工作台 / 全局搜索 / 在线状态                      │
├────────────────────────────────────────────────────────────┤
│ 账号 1  账号 2  添加账号 │ 扫码 连接 后台采集 暂停 重连       │
├───────────────┬───────────────────────────────┬────────────┤
│ 会话导航       │ WS 前台聊天（最大区域）         │ 辅助抽屉   │
│ 搜索/列表      │ 列表 + 对话 + 输入框             │ AI 分析    │
│ 仅一个滚动区   │ 不被采集脚本、抽屉或流程条覆盖    │ 客户档案   │
│ 可收缩为图标栏 │                               │ 回复建议   │
│               │                               │ 采集诊断   │
├───────────────┴───────────────────────────────┴────────────┤
│ 本地消息 / 导入（单行，可展开，不占用聊天高度）              │
├────────────────────────────────────────────────────────────┤
│ 列表同步 → 完整历史 → AI 分析 → 档案补齐 → 跟进任务（可收起） │
└────────────────────────────────────────────────────────────┘
```

## 交互规则

- 前台 WS 只负责用户聊天、搜索、切换会话和发送消息；后台采集不注入前台采集脚本，不滚动、不点击、不打开会话、不抢焦点。
- 关闭右侧辅助抽屉后，中间 WS 区域自动获得释放的宽度；关闭左侧导航后，中间区域继续扩展。
- “本地消息 / 导入”默认单行收起；展开时使用固定上限高度，不能挤压 WS 到不可用尺寸。
- 流程条默认显示五个状态数字，点击后进入对应工作区；完全收起后只保留一条状态轨。
- 仅允许一个垂直滚动 owner：会话列表、WS 原生页面和辅助抽屉各自有明确边界，父级页面不抢滚轮。
- 账号切换、后台采集和前台聊天均按账号隔离；切换账号不会复用旧账号的会话或辅助数据。
- 群发中心属于 WS 独立侧边栏，只针对当前账号和明确选择的会话或群组生成发送计划，不直接复用普通聊天输入框。
- 全量导出作为 WS 独立侧边栏入口，不塞进当前会话的辅助卡片；它可以选择当前账号或全部账号，任务进度显示在顶部状态带和任务中心。
- 群发必须经过目标筛选、内容预览、翻译预览、限速配置和确认后进入队列；支持暂停、取消、失败重试和逐条发送审计。
- 群发队列与后台采集队列分离，群发运行期间不能改变前台聊天窗口的滚动位置或当前会话。
- 未读会话继续跳过；群聊按既有规则采集；AI 只补齐已有客户档案的空字段，低置信度或冲突进入人工确认。

## 全量导出与群发附件

- WS 工作台提供“导出全部信息”：支持当前账号或全部账号，范围包括联系人、会话、普通群聊、VIP 群聊、群组目录、群成员快照、完整消息、消息方向、时间、原文、译文、客户关联、AI 分析、采集覆盖状态和发送审计。
- 导出采用流式压缩包，包含 contacts.json、groups.json、conversations.jsonl、messages.jsonl、media/ 和校验清单，不能一次性把所有消息装入浏览器内存。
- 对 WS 能取得的图片、视频、文档、音频等媒体，导出原始文件和媒体索引；如果 WS 未提供原文件，只导出文件名、MIME、大小、消息 ID、缩略图（若有）和 unavailable 获取状态。
- 群发中心支持文字、图片、视频、文档、音频和其他文件附件；附件可以带一段文字说明，文字与媒体作为同一条发送计划记录。
- 每个附件进入队列前都要校验类型、大小、哈希和当前账号权限；支持翻译文字说明、预览、限速、暂停、取消、重试和逐条发送审计。
- 多附件按明确顺序排队；某个附件失败只重试该条，不重复发送已成功的目标。当前前台聊天和后台采集不受附件队列影响。

## 视觉规范

- 采用现有 Horizon Atelier 深海蓝底、低饱和青绿和香槟金强调色。
- 结构以稳定几何和细边框为主，减少大面积发光、漂浮卡片和动态背景。
- 聊天区对比度最高，辅助抽屉次之，后台状态使用小型状态灯和数字，不使用闪烁动画。
- 群发中心使用独立的目标数量、队列状态和发送进度，不在聊天区弹出大块遮挡层。
- 客户、账号和统计使用实时数据；设计图中的“客户 A/B”等仅为占位，不写死业务内容。

## 性能边界

- 前台 WS WebView 与后台 Collector 不共享 DOM、滚动状态或窗口尺寸。
- ResizeObserver、刷新队列和状态更新必须合并到单帧/单请求，禁止重复整页渲染。
- 辅助抽屉和流程条只更新局部区域；消息列表、会话列表和任务列表保持分页/虚拟化。
- 每个后台任务必须具备取消、重试、队列上限和错误可见性；关闭页面不遗留轮询和事件监听。

## 非目标

- 不改变客户中心、群组管理、VIP、跟票、报名、入金、统计、GPT 或手机号登记的业务含义。
- 不把群发做成无审核的“一键全发”；群发始终保留可预览、可暂停、可取消和可追溯记录。
- 不恢复 Docker、PostgreSQL、Electron 或旧客户端入口。
- 不在本阶段新增数据字段或改变 AI 评分规则；本阶段只调整 WS 工作台布局、展示和交互边界。

## 验收标准

- 1440、1280、1060、900 像素宽度下，WS 前台都保持可聊天尺寸。
- 辅助抽屉、导入栏、流程条均可独立收起，收起后布局不跳动。
- 后台采集运行 30 分钟期间，前台不自动滚动、不打开会话、不闪屏、不抢焦点。
- 滚轮在会话列表、WS 页面、辅助抽屉之间不会串区；每个区域只有一个纵向滚动 owner。
- 设计确认后再进入实施计划和代码改造；本文件阶段不修改业务代码。
