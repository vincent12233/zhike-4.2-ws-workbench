# 知客视觉与布局统一整改设计

## 意图

在不改变知客现有业务逻辑、数据结构、统计口径和页面职责的前提下，统一桌面版与网页业务页的颜色、字号、间距、圆角、阴影和响应式布局，让工作台在常用桌面尺寸以及 820×540 小窗口中都清晰、稳定、可触达。重点解决当前多套 CSS 叠加、视觉过饱和、字号过小、断点分散、WS 三栏挤压和 WinUI/WebView2 缩放不稳定的问题。

## 目标

- 建立一套可追踪的视觉令牌，并让旧组件通过别名逐步使用同一组颜色和尺寸。
- 保留现有品牌方向（深蓝导航、青绿色主行动色、蓝色辅助色），减少无意义的紫色和多层渐变。
- 统一正文、辅助文字、表头和标题层级，正文不低于 13px，辅助信息不低于 11px，表头不低于 12px。
- 统一壳层尺寸：展开导航约 224px、折叠导航 64px、顶部栏 52px、内容边距 20px、底部状态栏 28px。
- 在 820×540、1280×720、1920×1080 以及 125%/150% 缩放下，按钮、筛选器、表格和 WS 面板均可触达，不出现页面级二次滚动。
- WS 页面在窗口尺寸变化时重新测量并完整裁剪 WebView/overlay 边界，保留左右侧栏收起和移动端面板切换。
- 默认关闭持续 Aurora/流动动画，只保留短促 hover/focus 反馈，并尊重 `prefers-reduced-motion`。

## 非目标与反目标

- 不重做页面信息架构，不删除或合并现有业务页面。
- 不修改客户、跟票、入金、报名、VIP、AI、WS 等业务规则、字段、统计口径或数据迁移逻辑。
- 不引入新的前端框架或 UI 依赖，不把桌面版改成网页版。
- 不以“更炫”为目标；持续动画、过度玻璃化、低对比文字和只适合大屏的固定三栏布局都视为失败。

## 现状依据

- `resources/app/styles.css`、`modules/v41-ui.css`、`modules/ui-refresh.css`、`modules/ws-workbench.css` 多次覆盖同一组件，圆角、阴影、字号和颜色不一致。
- `v41-ui.css` 对导航、主按钮和工作台横幅使用多层青/蓝/紫渐变与 Aurora 动画，造成视觉噪声和额外绘制开销。
- 现有断点分散在 1150、1050、900、850、820、760、650、600、560、480px，且 `body min-width` 在不同层中互相覆盖。
- WinUI `MainWindow.xaml` 使用 57px 原生顶栏与 820×540 硬最小尺寸；WS overlay 只在路由/打开时测量，窗口缩放时没有可靠的防抖重测和完整边界 clamp。

## 方案比较与选定方案

### 方案 A：统一设计令牌 + 增量覆盖（选定）

新增末尾加载的 `resources/app/modules/design-system.css`，以 alias token 统一既有 `--navy`、`--teal`、`--line`、`--soft` 等变量，覆盖核心组件和断点；同时对 WinUI 端补齐同名语义色刷、收紧顶栏，并修复 WS overlay 的 Resize/边界逻辑。旧 CSS 暂不删除，先通过契约和截图回归确认稳定后再清理。风险最小，可随时回滚，符合现有项目“保留原页面体系”的要求。

### 方案 B：重写为单一 CSS

删除并重排现有样式文件。视觉控制最彻底，但会触碰大量历史页面和模块，容易改变隐藏状态、空状态和表格行为，不适合本次增量整改。

### 方案 C：只改 WinUI 原生壳

只调整 XAML 和原生颜色。能改善窗口边框和顶栏，但网页业务页仍有多套视觉系统，无法解决用户看到的整体不统一问题。

## 设计基线

### 颜色

语义令牌固定为：背景 `#F4F7FB`、表面 `#FFFFFF`、柔和表面 `#F5F8FC`、边框 `#DCE6EF`、强边框 `#C7D8E5`、主文字 `#203449`、辅助文字 `#6B7F92`、主色 `#0EA991`、主色深色 `#087F70`、辅助蓝 `#2B79D3`、AI 强调紫仅用于 AI 标签、成功/警告/错误各一组高对比状态色。旧变量通过 alias 映射，业务模块不能直接新增散落颜色。

### 排版与间距

采用 4/8/12/16/24/32px 间距阶梯；控件圆角 8px、卡片 12px、大面板 16px；阴影统一为低对比 `0 4px 16px rgba(27,61,91,.08)`。正文 13px、辅助 11px、表头 12px、页面标题 22px、面板标题 14px；数字使用等宽数字特性，保证统计列对齐。

### 布局与断点

- 大桌面（>1200px）：导航 224px，内容区单一滚动容器，WS 使用三栏。
- 中等桌面（901–1200px）：导航默认折叠为 64px，缩短内容边距和工具栏间距，WS 允许侧栏切换为 rail。
- 小窗口（≤900px）：页面按单栏/移动面板展示，WS 使用现有 mobile tabs，不强制三栏最小宽度。
- 仅保留 1200、900、640 三个主断点；组件内部只允许为可验证的特殊控件增加局部规则。

### 动效与可访问性

默认静态背景和静态渐变；hover/focus 反馈不超过 180ms。所有交互控件保留 focus-visible 轮廓，颜色对比满足可读性；`prefers-reduced-motion` 或用户关闭动效时彻底禁用动画。

### WS 与 WinUI

- `design-system.css` 统一 WS 卡片、工具栏、空状态、消息和 AI 状态色，深色主题不再使用硬编码白色。
- WinUI 语义刷与网页 token 对齐；原生顶栏收紧到 52px，兼容模式不额外占用 WS 画布。
- Legacy/WebView2 host 在尺寸变化时以 150ms 防抖重新测量 WS overlay；`x/y/width/height` 全部 clamp 到 host bounds，并处理 DPI/滚动偏移。
- 维持现有侧栏收起、WS 左右面板收起、多账号和登录状态逻辑不变。

### 实施口径（已落定）

- 覆盖范围是所有现有业务路由、共享导航/顶部栏、弹窗、空状态、表格以及 WS 子面板；验收截图优先覆盖首页、客户中心、快速录入、任务、看板和 WS。
- 宽表格和工具栏在小窗口使用已有的内部横向滚动容器，数据列不换行、不隐式删除；优先保证字段可读和操作可触达。
- WS 在逻辑宽度 `>1200` 使用完整三栏；`901–1200` 默认允许左右侧栏折叠为 52px rail；`<=900` 使用移动面板 tabs，默认显示中间聊天面板，收起/展开状态沿用用户上次选择。
- WinUI 的 52px 指客户区内容顶栏高度，不包含 Windows 系统标题栏/最小化/最大化/关闭区域；WebView host 从客户区剩余高度计算。
- 状态色固定为成功 `#167A52` / 成功底 `#E7F6EE`、警告 `#9A6410` / 警告底 `#FFF2D8`、错误 `#A23A32` / 错误底 `#FFEAE7`、AI 紫 `#7357C7` / AI 底 `#F0EBFF`，正文/边框仍遵守主令牌对比度。
- WebView2 不改变用户页面缩放，按 100% CSS 逻辑坐标测量；WinUI DPI 只在宿主边界转换一次，尺寸变化使用防抖重测，避免重复缩放。

## 触及范围

- 新增：`resources/app/modules/design-system.css`。
- 修改：`resources/app/index.html`（末尾加载新层）、`resources/app/server.mjs`（静态资源白名单）、现有视觉契约测试。
- 修改：`desktop/src/Zhike.Desktop/App.xaml`、`MainWindow.xaml`、`Views/LegacyUiHostPage.xaml(.cs)` 及必要的 WS 容器样式。
- 不修改：业务模块 JavaScript、数据库迁移、API 数据契约和用户数据目录。

## 验收

- 视觉契约检查新 token、字号下限、主断点、默认无持续动画和资源白名单。
- 现有完整回归测试继续通过，新增 820×540/125%/150% 布局检查和 WS overlay clamp/resize 检查。
- 在安装版实际截图确认首页、客户中心、快速录入、任务、看板、WS 工作台的主导航、卡片、表格、空状态和按钮风格一致。
- 业务数据仅读验证；不导入、不清空、不迁移真实客户数据。
- 若任一视觉层回归失败，可移除 `design-system.css` 并恢复旧 XAML 令牌，不影响业务数据和 API。
