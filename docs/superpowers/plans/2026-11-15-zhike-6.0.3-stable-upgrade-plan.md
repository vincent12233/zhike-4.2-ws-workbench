# Zhike 6.0.3 一次性稳定升级实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变既有业务规则的前提下，完成 WS、群组、AI、翻译、任务、性能、存储和发布质量的一次性升级。

**Architecture:** 以 Node SQLite 事实表和领域服务为核心，前台 WebView 与后台 Collector 完全隔离；前端按增量事件更新，列表使用真实分页/虚拟化，UI 线程不执行重任务。

**Tech Stack:** WinUI 3、WebView2、Node.js、SQLite、原生 JavaScript/CSS、C# 服务、现有测试脚本。

**Spec:** `docs/superpowers/specs/2026-11-15-zhike-6.0.3-stable-upgrade-design.md`

## Global Constraints

- 不恢复 Docker、PostgreSQL、Electron 或旧客户端。
- 保留客户、VIP、跟票、报名、入金、统计、WS、GPT 和手机号登记业务语义。
- 业务记录独立，手机号关联客户主档案。
- 未读会话跳过；审核状态不计入已进群。
- AI 低置信度和冲突进入人工确认；普通聊天分析不得无条件新建客户。
- 前台 WS 可正常聊天，后台采集不得滚动、点击、切换或改变前台布局。
- 每个滚动区域只能有一个垂直 scroll owner。
- 所有新行为先写失败测试，再实现，再运行全量测试。

## Review Focus

- 登录后未渲染的群组仍能被发现并加入监测。
- 后台采集不改变前台 WS 的滚动、窗口尺寸和当前会话。
- 多账号不能串消息、客户、群组或 AI 结果。
- 混合渠道导入逐行分类，低置信度不静默归入“群粉”。
- 低置信度 AI 不能覆盖原值，也不能创建重复客户。
- 大量客户、消息和任务不会通过全量重绘导致卡顿。
- 删除、回收、恢复不会留下 AI、WS、群组和任务孤儿记录。
- 发布包必须与当前 sourceCommit 一致。
