## 阶段 1B：单写入者与 fencing（仍限隔离环境）

1. 引入写入所有权记录：workspace/account、writer role、generation/fencing token、lease、expiry、holder PID、协议版本。
2. 所有写 API 在事务边界校验 fencing；旧 generation 返回 `StaleFence`，不能只靠内存互斥锁。
3. claim、checkpoint、分析结果、CRM 关系和群事件都使用同一写入协调合同。
4. 故障注入：进程崩溃、租约过期、重复提交、DB busy、写入中断、时钟偏移。
5. 通过后才可在测试工作区使用 `collector.writer=shadow`；仍不允许生产写。

## 阶段 1C：IPC 与 Worker 预生产验证

1. 保留动态 loopback 端口，增加 Windows 用户 SID/父进程/能力范围验证；若改用命名管道，必须先完成 ACL 真实测试。
2. 固定协议 envelope：`schemaVersion/requestId/correlationId/accountId/capability/idempotencyKey/fencingToken/deadline`。
3. 明确错误分类、心跳、取消、超时、断线恢复、日志脱敏和 token 轮换。
4. Worker 只读取测试账号/脱敏数据或明确隔离账号；不得读取生产 SQLite。
5. 长跑、资源预算和崩溃恢复通过后，提交阶段 1 实施复核。

## 阶段 1D：群组管理契约

1. 冻结 `account + group_jid` catalog 与 profile/target 的关系，消除重复目标。
2. 冻结 `joined/left/removed`、审核状态、`event_at/observed_at` 和 idempotency 语义。
3. 实现全局客户查重、确定性新成员登记和客户群关系事务；普通 WS AI 无自动建档能力。
4. 让渠道/来源从系统设置稳定 ID 进入事件和统计；未知来源进入待绑定。
5. checkpoint 只在事件事实和登记事务完成或 durable review 已落库后推进。
