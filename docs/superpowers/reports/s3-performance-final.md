## 测量前确认的调查判据

- 复用阶段 5.2 的 15 分钟连续观测建议。每轮从同一路由、同一窗口状态和同一隔离账号开始，暖机后至少重复三轮。末轮回到同状态后持续空闲至少三分钟。记录循环始末、末段空闲始末及正常关闭。
- 主控在受控性能阶段开始前确认以下调查触发线，适用范围为同状态对比。若暖机后同状态循环结束点与后续空闲均呈持续正增长，且 Private Bytes 净增达 64 MiB、句柄达 1,024、线程/GDI/USER 任一达 32，或等价操作状态中新 Core 或 WebView 进程持续增加，需定位来源。冷启动与首次初始化阶跃单列。工作集和 Private Bytes 回落据实报告。单独峰值不足以确定泄漏。
- 页面与账号动作均须完成应用就绪判据。记录时延原值、次数、中位数和最大值。项目现有证据缺少公开响应 SLA。尾样和只读复查均须证明观察到的 PID + 启动时间身份正常释放。退出耗时报告采样上下界和原生停机事件。

## 操作和采样

1. 为运行准备合成客户、两个隔离账号、群组及成员。账本标记开始后，从首页进入 CRM 客户中心，打开合成客户档案再关闭，返回首页。
2. 打开 WS 工作台 → 群组列表 → 打开并收起同一群组详情 → 群成员列表。返回 CRM，在客户中心打开并关闭新增客户弹窗，取消或关闭且不保存。
3. 进入 WS「账号与连接」选择另一隔离账号，确认切换完成。再次回到原测试账号及初始路由后记录循环结束，以便比较同状态检查点。
4. 空闲结束后保留就绪读取，标记关闭请求并正常关闭应用。采样器覆盖观测身份释放。用独立只读命令复查身份。

`resource-observe.ps1` 保留默认样本数和 1–120 秒的间隔范围，将硬上限从 361 扩至 3,600。当前方案用 2 秒请求间隔，等待首样落盘后操作，并启用 20 条退出尾。实际间隔包含进程查询耗时。标记仅记录操作窗口。隔离 fixture 就绪探针另以 WebView2 的可信 DOM 输入时间为起点，在应用就绪谓词首次满足并跨下一帧保持时记录两帧时间。采集窗口不把 GUI 工具传输或等待耗时计入 UI 时延。 [采样器](../../../scripts/stage52/resource-observe.ps1) [隔离就绪探针](../../../scripts/stage52/resource-readiness-probe.cjs)

### UI 响应、异常和待测

本轮未开始专门的性能操作窗口，CRM、群组、成员、弹窗和双账号的受控重复循环均没有测量结论。原生截图未出现计时面板。已核对当轮加载的隔离 HTML 确实含初版探针。初版在 Document 上处理 `DOMContentLoaded`，先于 Window 上设置隔离标记的宿主监听器执行，导致探针初始化门槛提前检查。提交 `2f0ec18` 将监听器放到宿主同一事件目标上。专项 Node 回归保留旧实现的预期失败（退出码 1）和修复后 1/1 Passed（退出码 0）。用户已暂缓本轮后续桌面验收。新探针启动和真实操作时延留待下一次独占 GUI 复验。当前缺失来自计时工具，未测得产品卡顿时间。

### 计时探针边界复验

复核发现，切号采用同步乐观渲染。原探针收到对正在切入账号的第二次点击时会重启计时，随后可能把首次切号的完成归到第二次点击。探针现以页面呈现的账号标识忽略这类重复选择，保留首次可信输入的时点。中断在途任务会写入一条记录，探针在写入后重新检查容量，确保每次导出最多 192 条。

`node --test scripts/stage52/resource-readiness-probe.test.cjs` 在独立工作树执行，1/1 Passed，退出码 0。保留启动顺序、可信事件和账号就绪断言，增验切入期间与切换完成后的重复点击，以及 191 条已记录并中断在途任务的容量边界。本次为 VM 复验，真实界面的受控性能测量仍为 `NotTested`。
