# 知客 6.0.1 Horizon Atelier 发布说明

状态：候选版。包含新轮廓的开发安装包已覆盖安装并在本机启动检查；自动化完整回归 150/150 通过、安装合同 8/8 通过。正式 ReleaseGate 包、全模块视觉、真实 WS 登录与外部 AI 联调仍需验收。以 [测试报告](test-report-6.0.1.md) 的实际结果为准。

6.0.1 保留现有客户、群组、VIP、跟票、报名、入金、任务、看板、统计等业务规则，使用一套 WinUI 3 + WebView2 + 本机 SQLite 桌面运行链。6.0 系列使用独立的 `%LOCALAPPDATA%\Zhike6` 数据目录，不预置演示客户；覆盖 6.0 时复用该目录，不主动读取或删除旧版 `%LOCALAPPDATA%\Zhike`。

## 本轮实现

- 今日工作台按 Horizon Atelier 参考图重新组织侧边栏、顶栏、AI 跟进流域、业务指标、动态和趋势。客户、金额、数量由当前本机数据和有效 AI 提醒生成；装饰波形不承载示例客户或固定业务值。原有明细收在可展开区域，入口和统计口径保留。
- AI 跟进流域按服务返回的提醒呈现加载、空结果、失败和重试状态；不把本地排序结果伪装成 AI 分析。
- 工作、客户、业务和系统导航保留全部入口。展开侧边栏使用接近参考图的连续收腰和底部外扩轮廓并支持折叠；调整导航留白、固定单行标签，避免 Windows 缩放下挤成竖排。新版开发包已在 1422×815 原生 WebView2 窗口中检查轮廓与菜单文字。
- 群组统计卡在本轮检查的桌面窗口中并列展示，分类与进退群明细继续读取系统设置中的渠道。客户、业务、任务、手机号登记、WS 和 GPT 页面统一了深色面板、表单、按钮、表格和空状态的视觉层次。
- 页面切换时重置工作区滚动位置；修正业务摘要缓存，使同一条入金记录编辑金额或状态后能刷新指标。
- WS 工作台收紧顶部控制栏，增加嵌入页可用高度，保留左右栏折叠和聊天导入区折叠。原生 WebView2 移除了将 WhatsApp 文档缩至 80% 的注入，修复页面底部空白带；本机安装版在内层滚动后可以完整看到登录二维码。本人扫码和登录后聊天仍未验证。
- WinUI 原生标题栏使用 Horizon 深色样式和版本化图标；资源与构建脚本统一锁定 6.0.1，正式发布门禁拒绝混入旧资源。

## 现有业务链

- 客户主档按身份或号码关联；跟票的不同股票、买卖时间和批次保持独立记录，手机号登记是独立模块。
- WS 列表、实时消息和完整历史采集按各自完成状态显示；后台任务跳过未读会话。用户本人明确绑定的 VIP 群按成员可信身份归到已存在的客户；普通群及类型不明会话不自动补档或提醒。
- AI 仅补唯一匹配的现有客户空字段，不新建陌生客户，不覆盖人工或锁定字段；跟进优先级依据资金实力与聊天粘度，股票投资年限只用于档案。外部服务异常时保留原文和重试入口。
- 数据中心仅恢复 6.0 自身备份并核对完整性；备份和恢复逻辑已由隔离数据回归覆盖。

## 使用边界

- 个人 WhatsApp Web 没有可供本项目直接导出全部历史的官方接口。历史采集依赖本机运行期间逐会话加载，断网、休眠、退出或登录过期时暂停；WhatsApp 页面结构改变可能使采集失效。
- 本轮自动化测试不能代替本人扫码、多账号切换、手机端消息同步、真实 AI 服务分析与实际客户字段写入的联调。这些项目尚未被记录为通过。
- 参考图是视觉目标。本轮已检查新版侧边栏、首页、群组和 WS 登录二维码的实际窗口；仍未逐页完成所有窗口尺寸与缩放比例的视觉验收，不能宣称每个模块与参考图达到像素级一致。当前窗口的 WS 登录二维码需要在内层滚动后查看。
- 开发安装包未签名；正式交付前须以最终安装包 SHA-256 和 ReleaseGate 清单重新核验。编译成功不等于验收通过。
