# 知客 6.1.0 Horizon Atelier 本机桌面版部署

知客桌面版使用 WinUI 3、WebView2 和随包 Node SQLite 服务。客户、业务记录、导入、统计和本机备份可以离线使用。WhatsApp 前台会话和用户调用的外部 AI 服务需要联网。

## 安装

登录有该私有仓库访问权限的 GitHub 账号，从 GitHub Releases 的预发行 `v6.1.0-rc.1` 条目获取 `zhike-6.1.0-win-x64-setup.exe` 和同次 `release-output-manifest.json`。默认安装到 `%LOCALAPPDATA%\Programs\ZhikeNative`。安装器应创建开始菜单和桌面快捷方式，并在安装结束后启动知客；覆盖安装、卸载后数据保持和实机操作仍以目标机验收记录为准。

安装器要求 Windows x64、系统内部版本 22621 或以上。运行安装器前须安装 Microsoft Edge WebView2 Evergreen Runtime。缺少时安装器会在修改文件或处理旧客户端前中止。交互安装可打开微软下载页，安装依赖后请重新运行知客安装器。静默安装会直接失败并记录缺失依赖。自包含安装包已提供 .NET、Windows App SDK 与 Node。干净 Windows、覆盖升级及卸载仍待实机验证。

安装前对照本次清单核验安装器 SHA-256，并查看候选发布项记录的签名状态。若未签名，Windows 可能提示未知发布者。请保留系统安全保护。

## 最短首次使用

1. 已有旧版资料时，先在旧版“数据中心”导出备份或可重新导入的 CSV / Excel，再运行安装器。知客 6.1 不会自动读取或迁移旧 `%LOCALAPPDATA%\Zhike`。
2. 从桌面或开始菜单打开“知客工作台”。首次启动先等待本机服务完成连接；看到顶部“已保存到本机”后再开始录入。若持续提示连接失败，按[故障排查](local-desktop-troubleshooting.md)处理，不要删除数据库或锁文件。
3. 在“客户中心”新增一位客户，或在“快速录入”预览并保存资料。确认顶部没有“保存异常”“同步异常”或“数据冲突”。
4. 立即进入“数据中心”选择“创建 JSON 备份”，确认下载的文件实际存在，再复制到当前电脑之外的安全位置。数据库内的自动快照不能代替外置备份。
5. 需要 WS 时进入“WS 工作台”，在官方页面由本人扫码或登录；需要 AI 时进入“GPT 运营助手”自行配置服务和 API Key。两者都需要联网，后台自动采集和自动 AI 处理当前保持关闭。

## 数据目录

6.0 业务数据只保存在 `%LOCALAPPDATA%\Zhike6`，主数据库为 `workspace.sqlite`；首次启动创建空库，不预置演示数据。系统不会读取或迁移旧 `%LOCALAPPDATA%\Zhike`，也不会主动删除旧目录。自动写入前快照保存在新数据库中；SQLite 运行时可能同时出现 `workspace.sqlite-wal`、`workspace.sqlite-shm`，本机服务运行时还会使用 `.workbench.lock`。卸载程序不会删除 6.0 数据目录；覆盖升级也不会覆盖业务数据。

当前正式版不会创建 `%LOCALAPPDATA%\Zhike6\logs` 持久日志目录。本机服务标准输出和错误输出仅转发到 WinUI 调试输出；排查时以界面错误信息、数据目录状态和交付目录中的独立安装验收记录为准，不要删除 `workspace.sqlite`。

## WS 与 AI

|能力|当前可用范围|
|---|---|
|WS 前台聊天|从 WS 工作台打开前台聊天，选择账号并自行完成扫码或登录。可在官方页面阅读、发送消息及切换账号。每个账号使用独立的 WebView2 会话。|
|WS 手动导入与本机目录|在前台打开获准处理的会话，手动导入当前可见内容或选中的文字。联系人、群组和审计页面展示已保存的本机记录。|
|WS 后台能力|自动会话发现、后台采集、自动完整历史和后台群监测当前不可用。已有记录、队列和断点仍可查看。|
|离线 AI 相关资料|不配置外部服务也可以查看本机已保存的摘要、待确认建议和跟进记录。新生成内容和外部翻译需要相应的联网服务。|
|显式联网 AI|从 GPT 运营助手的“设置 API Key”或 WS 工作台设置打开“GPT 本机设置”。选服务商和模型，输入 API Key 并保存。需要确认服务是否可达时，可运行“测试连接”。连接测试发送测试文字。主动提交分析时，所选范围内的客户上下文、输入内容和附件会发送给选定的服务商。已有配置只表明本机保存了密钥，实际连接以测试或请求结果为准。|

WhatsApp 的登录、扫码、验证码和密码由用户本人在官方页面处理。已导入的消息与已有客户业务资料保存在本机 SQLite。VIP 群手动导入会按可信 JID 或手机号区分发言人，只有唯一匹配到现有客户的消息才可用于其个人档案和跟进评分。匹配冲突保留待处理。已有 WS 脱敏诊断的位置为 `%LOCALAPPDATA%\Zhike6\diagnostics\ws-collector.jsonl`，文件上限为 256 KB。

API Key 按服务商在本机加密保存。生产 Worker、自动 AI 消费者和认证 profile 复制保持关闭。AI 建议与拟议业务写入由用户核对和确认。部署后的真实 WS 连接和外部 AI 结果以目标机验收记录为准。

## 备份与恢复

在“数据中心”执行本机备份或导出。完整备份包含所有已登记的 WS 账号；账号清单或任一账号导出失败时不会生成标记为完整的文件。原生自动备份带 SHA-256 完整性封装，只导入符合知客 6 系列备份格式且校验通过的 JSON 文件。恢复先创建写入前快照，逐账号写入失败时恢复原会话并撤销本次新增账号。旧版数据目录和旧版备份不会被自动读取或迁移。

手动备份完成后，应在下载目录确认 JSON 文件存在且大小不为 0，再复制到其他磁盘或受控存储。要启用定时备份，请在“系统设置”的“跟进提醒与自动备份”中选择目录、设置间隔和保留份数，启用后先执行一次“立即备份”并确认状态。定时备份只在知客运行期间执行，不包含 AI API Key；WhatsApp 登录会话也不能作为换机凭据。

恢复时进入“数据中心”选择“从备份恢复”，核对客户、跟票、入金和跟进数量差异后再确认。恢复会替换当前工作区，并先在当前数据库内创建快照；完成后应逐页核对主要数量和最近记录。换机后仍须重新登录 WhatsApp，并重新配置 AI Key。

当前自动备份单次上限：客户状态 95 MB、单个 WS 账号 48 MB、完整备份文件 250 MB，并有对应记录数限制。超限会提示失败，避免留下不能恢复的文件。自动保留策略仅清理自动备份目录顶层、文件名符合“知客自动备份_日期_时间.json”规则的旧文件，不清理其他文件。换机恢复请同时保留完整备份和 SHA-256 校验信息；WhatsApp 登录与 AI 密钥须在新电脑重新配置。

## 回滚

先导出当前 6.1 备份，再关闭知客并开始回滚。需要恢复旧版本时，使用已验证的旧安装器和升级前备份。旧版本能否直接读取已由 6.1 写入的业务库仍待验证。请保留原库和两份备份。

## 交付验收

自动化测试报告不能替代安装后的实机验收。最终安装包的版本、哈希、覆盖安装数据保持、快捷方式、WS、手机同步和 AI 结果，只以交付目录中单独生成的安装验收记录为准。
