# 保存异常修复记录

## 根因

WinUI 桌面壳在未完成 Docker/API 配对时仍强制将 `__LOCAL_DB__` 设为 `true`。页面因此把本应写入本机浏览器存储的数据发送到 `/api/state`，而桌面桥没有可用的 API 地址或会话令牌，最终被显示为“保存异常”。Docker PostgreSQL、API 和 Worker 健康检查均正常。

## 修复

- 桌面桥按是否存在有效会话令牌注入本地/远端保存模式；未配对时沿用原有 localStorage 保存路径。
- 未启用远端模式时，不再把 `/api/*` 请求转发到空的远端桥接客户端。
- 服务端 400/401/409 错误正文透传到页面，保留校验失败、会话过期和版本冲突的具体原因。
- 后台同步读取异常与保存写入异常分开显示，避免把同步故障误报成“保存异常”。
- 空白的 `ZHIKE_API_*` 环境变量不再覆盖已保存的桌面配对配置，避免升级后误切到失效连接。
- 修复右上角关闭：WebView2 关闭前刷新改为同步启动、轮询确认，并增加宿主侧超时；刷新失败也不会永久拦截用户的关闭请求。
- 将 `zhike.ico` 同步应用到原生窗口标题栏，避免安装后仍显示系统默认角标。
- 新增桌面保存回归契约，覆盖无配对模式、错误正文透传和同步错误分类。

## 验证

- `node scripts/run-tests.cjs all`：56/56 通过。
- `node tests/server-v2/run-all.cjs`：19/19 通过。
- WinUI Release `win-x64` 编译：0 警告、0 错误。

## 使用边界

未配对时数据保存在当前桌面 WebView 的本机存储中；需要 PostgreSQL 多窗口同步时，仍需在桌面端完成服务器配对。配对或会话恢复后重启桌面应用，使桥接模式重新初始化。
